# Data tables and scripts

`src/data` holds the tables the game and renderer read: object shapes and 2-D pictures from the vector ROM, the attract texts, the enemy Choreography, the Surface Mazes, the Trench Wedges and Pies, the Death Star's city lights, and the encoded speech Words. Every file is data only, with no logic. Most were traced from the original's object tables and listing; one is generated by an `npm` script from macOS `say`; a git-ignored subdirectory receives what the extraction scripts decode from a local copy of the original. What may and may not enter the repository is fixed by [ADR 0001](../adr/0001-what-is-copied-from-the-original.md).

## The rule

The ADR draws the line as follows. Copied, as data: object shapes (vertex tables and draw programs traced from the vector ROM), the POKEY sound-effect tables, and the rules, timings, spawn patterns, scoring and on-screen text, verbatim. Not copied: the speech ROMs (film actors), the music tables (the film score), and the ROM files and Atari source themselves; no routine is ported line by line. The 2026-09-13 amendment allows the real music and speech to be heard locally: `scripts/extractMusic.ts` and `scripts/extractSpeech.ts` decode them into `src/data/local/`, which `.gitignore` excludes along with `local.config.json`.

Consequence for a contributor: anything under `src/data/local/` and any path in `local.config.json` must never be committed, and nothing from them may be pasted into code, tests or docs.

### Units and frames

Each file states its own coordinate frame in its header, and they differ:

| File | Frame | Unit |
|---|---|---|
| vectorRom.ts models | original model frame, +X forward, +Y right, +Z up | model units × `scale` × 2 for world units |
| vectorRom.ts pictures, hud.ts, attract.ts, logo.ts | vector-generator screen, +X right, +Y up | screen units |
| surface.ts buildings | X forward, Y right, Z up from the ground | `BUILDING_UNIT` = 240 universe units |
| surface.ts Mazes | `right` along +Y, `forward` along +X | universe units |
| trench.ts models | x forward, y from the wall toward the centre, z up | `TRENCH_UNIT` = 16 universe units |
| trench.ts Wedges | row `length` | universe units, 2048 or 4096 |
| deathStarLights.ts | vector units at the lights' own scale | three binary steps larger than `DEATH_STAR_DETAIL` |

The [Coordinates](./coordinates.md) page explains how the renderer maps these to Three.js.

## The files

### vectorRom.ts

```ts
export interface RomModel {
  readonly points: readonly (readonly [number, number, number])[];
  readonly scale: number;
  readonly lines: readonly (readonly [number, number])[];
}
export type Polyline = readonly (readonly [number, number])[];
```

3-D models are in the original's model frame (+X forward, +Y right, +Z up, left-handed) in model units; point 0 is the centre. Multiply by `scale` for the size the original's maths used and by 2 again for world units; convert to Three.js with `(x, y, z) -> (y, z, -x)`. The models are `TIE_FIGHTER`, its three break-up pieces `TIE_PIECE_PORT_WING`, `TIE_PIECE_STBD_WING` and `TIE_PIECE_CABIN`, and `DARTHS_SHIP`. The 2-D pictures, in vector-generator screen units, are `CURSOR`, the Fireball sparkle bases `FIREBALL_BASES` with `FIREBALL_FUSE_TIPS`, `FIREBALL_TIPS` and `FIREBALL_HURT_TIPS`, the `FLASH_COLOUR_CYCLE`, the four `LASER_SPLASHES` and the `LASER_COLOURS` sequence along a bolt.

### hud.ts

```ts
export interface Stroke {
  readonly color: string;
  readonly lum: number;
  readonly intensity: number;
  readonly points: readonly (readonly [number, number])[];
}
```

All coordinates are screen units with the origin at the centre. `COCKPIT` holds the X-Wing's guns and hood by the original's labels, shifted by the Yoke through `COCKPIT_SHIFT`. `GAUGE` holds the ten shield gauge pictures as right and left halves about `GAUGE_BASE`, with `GAUGE_TITLE` and `GAUGE_DIGIT`. `HUD_TEXT` places the score and wave labels and digits. `FONT` is the vector font, strokes per glyph in a 24-unit cell 16 wide and 24 tall, with `FONT_ADVANCE` and `FONT_HEIGHT` both 24. `DEATH_STAR_MINI` is the miniature drawn in the Dogfight and `DEATH_STAR_DETAIL` the pictures of the Approach, keyed by the original's labels.

### logo.ts

`LOGO` is a list of `LogoStroke` (`intensity`, `points`) in raw picture units relative to the Banner's vanishing point, `LOGO_VANISHING_POINT` at (0, 408): outlines and the drop lines that give the letters their extruded look.

### attract.ts

`Message` is `{ text, x, y, color }` with the position at the lower-left of the first character. The exports are `INSTRUCTIONS` and `INSTRUCTIONS_DIGIT` (the flight instructions and where the Starting Shields count is stamped), `SCORING_PAGE`, `STORYLINE` (each line's x from the vanishing point and the Banner frame it starts on), `COPYRIGHT`, the High Score Table title and row positions for the Attract and for Initials Entry, `HIGH_SCORE_DEFAULTS` (the default table's ten initials and scores, which `defaultHighScores` in `game/state.ts` turns into rows), `INITIALS_MESSAGES`, `INITIALS_ALPHABET` (the letter grid with `RUB` and `END`) and `COIN_TEXT`.

### choreography.ts

`PROGRAM` is the whole Choreography as a list of `RomOp` values: `ct` (frames and a set of `FlagName` moves), `until` and `if` on a `StatusName` mask, `goto`, `gosub` and `return`, with targets as indices into the list. `ENTRY` maps the original's script labels to indices, `START_SPOTS` gives the spawn positions, `LEVEL_LISTS` the groups of `{ kind, spot, script }` a wave draws from, and `WAVE_SETS` the list names per wave (index 0 is displayed wave 1; waves 6 and up use set 5 when even and set 6 when odd). The reference is [choreography.md](../reference/choreography.md).

### surface.ts

This file is 3 500 lines because `MAZES` lists every building of every Maze. The head defines `GROUND_POINTS`, the 16-point spire every building is cut from, `BUILDING_UNIT` (240 universe units per model unit), and `BuildingPart` (`part: 'base' | 'top'` with its lines) for `TOWER`, `TOWER_STUB` and `BUNKER`. `FragmentModel` shapes are the six break-up pieces `TOWER_PIECE_LEFT`, `TOWER_PIECE_CENTRE`, `TOWER_PIECE_RIGHT` and the three `BUNKER_PIECE_*`. A `MazeEntry` is `{ type: 'tower' | 'bishop' | 'bunker', right, forward, sequence }` in universe units, `sequence` being the Lap on which the building awakens. `MAZE_BY_WAVE` maps displayed wave numbers to Maze names from wave 2 (wave 1 has no Surface) and `RANDOM_MAZES` names the six chosen at random from wave 21.

### trench.ts

`TRENCH_UNIT` is 16 universe units per model unit. `TrenchModel` (`points`, `parts` of colour, luminance and lines) describes `WALL_PANEL`, `WALL_GUN`, `CATWALK` and `EXHAUST_PORT`. A `WedgeRow` has a `length` (2048 short or 4096 long) and for each wall four Band values top to bottom: 0 empty, 1 panel, 2 Catwalk, 3 gun. `WEDGES` maps Wedge names to rows, `WEDGE_ENDS` records how each ends, and `PIES` lists the Wedge sequence per wave (`PIE1` for displayed wave 1). `TRENCH_MESSAGES` records the Trench's on-screen texts with their positions and conditions as notes from the extraction.

### deathStarLights.ts

The only traced file with a generator line: its header says it was produced by `decode_lights.mjs` in a reference directory outside this repository from `WSVROM.MAC`. `DEATH_STAR_LIGHTS_EVEN` and `DEATH_STAR_LIGHTS_ODD` are lists of `LightStamp` (`dots` and faint `lines`) in vector units at the lights' own scale. Even waves spell MAY THE FORCE / BE WITH YOU and odd waves carry the designers' names.

### speech.ts

`SPEECH_WORDS: Record<string, { frames: number; data: string }>` maps each Word to its frame count (25 ms each, the last a stop frame) and the packed TMS5220 frames as hex. It is written by `npm run speech` and must not be edited by hand; see the [Speech](speech.md) page for the pipeline.

## Local files

`local.config.json` at the repository root is git-ignored and has two optional keys:

| Key | Used by | Points at |
|---|---|---|
| `atariSource` | `scripts/extractMusic.ts` | a directory or zip holding the Atari listing (`SWMUS.MAC` is read) |
| `romSet` | `scripts/extractSpeech.ts` | the MAME zip or a directory of its files (`136021.107` is read) |

A leading `~` is expanded. The scripts write to `src/data/local/`, which is also git-ignored. The audio modules find the files with `import.meta.glob('../data/local/music.ts', { eager: true })` and the same for `speech.ts`: with the file absent the glob is empty, the exported `ORIGINAL_MUSIC` or `ORIGINAL_SPEECH` is `null`, and the game uses this project's cues and voices. With the files present the original plays by default; `?music=ours` and `?speech=ours` on the URL bring ours back. The tests that read the local files return early when they are absent.

## Scripts

The `scripts/` directory at the repository root holds the offline tools; `tsconfig.json` includes it so they are type-checked with the game. They run under Node directly as TypeScript.

| Script | npm script | Input | Output |
|---|---|---|---|
| [encodeSpeech.ts](../../scripts/encodeSpeech.ts) | `npm run speech` | macOS `say` for every Word in `SPEECH_LINES` | `src/data/speech.ts` (committed) |
| [lpc.ts](../../scripts/lpc.ts) | (library) | 8 kHz samples | `Frame[]` and packed bytes; imported by `encodeSpeech.ts` and `speech.test.ts` |
| [extractMusic.ts](../../scripts/extractMusic.ts) | `npm run music` | `SWMUS.MAC` from `atariSource` | `src/data/local/music.ts` (git-ignored) |
| [extractSpeech.ts](../../scripts/extractSpeech.ts) | `npm run speech:original` | `136021.107` from `romSet` | `src/data/local/speech.ts` (git-ignored) |

The other `package.json` scripts are `dev`, `build` (`tsc --noEmit && vite build`), `preview`, `test`, `test:watch`, and `docs:dev`, `docs:build` and `docs:preview` for this site.

`lpc.ts` contains the LPC analysis, pitch detection, breath synthesis and frame packing; `encodeSpeech.ts` is the driver that calls `say` and writes the file. `extractMusic.ts` assembles the listing's `.BYTE`, `.WORD`, `.GOSUB` and `.RETURN` lines into one byte image with the tune directory from `TUNTAB`. `extractSpeech.ts` reads the phrase table at 0x4002, bit-reverses each phrase, and counts frames by running it through the chip core evaluated from `TMS5220_CORE_SOURCE`. The [Music](./music.md) and [Speech](./speech.md) pages describe each in detail.

All three executable scripts import from `src/audio` (the line and speaker tables, the chip tables and core, the `OriginalMusic` type) rather than the other way round, so the game never depends on `scripts/`. The exception in the test tree is [speech.test.ts](../../src/audio/speech.test.ts), which imports `scripts/lpc.ts` to test the encoder.

## Tests that guard the data

The data files have no tests of their own, but the modules that read them do, and those tests pin the values the game depends on:

| Test file | What it checks against the data |
|---|---|
| [attract.test.ts](../../src/game/attract/attract.test.ts) | the Attract cycle on the original's timings, the Storyline lines starting at their alarms, the arcade default High Score Table, and Initials Entry (`END`, `RUB`, the timeout) from `attract.ts` |
| [scripts.test.ts](../../src/game/dogfight/scripts.test.ts) | the Choreography interpreter; that every `ENTRY` is inside `PROGRAM` and every jump in range; that every script runs a thousand frames without falling off the program |
| [surface.test.ts](../../src/game/surface/surface.test.ts) | loading the Maze for a wave with its towers counted, Laps, collisions with towers and bunkers, and the transition, from `surface.ts` |
| [trench.test.ts](../../src/game/trench/trench.test.ts) | the fixed Pie for a wave and its length, Catwalk hits by Band, Trench Turrets and the Exhaust Port from `trench.ts` |
| [speech.test.ts](../../src/audio/speech.test.ts) | every Word in `speech.ts` decodes through the chip model, ends with a stop frame, and is mostly loud |
| [effects.test.ts](../../src/audio/effects.test.ts), [music.test.ts](../../src/audio/music.test.ts) | every name the simulation raises exists in the audio tables (these read `src/game` as raw text) |

The two local-file tests, in `music.test.ts` and `speech.test.ts`, run only when `src/data/local/` is populated and pass trivially otherwise, so a fresh clone's test run does not depend on the original.

## Re-tracing a table

When a shape or table looks wrong against MAME:

1. Find the reference note for the file in the table above and the original label named in the file's comment.
2. Re-derive the numbers from the original's table, not by adjusting the TypeScript until it looks right; the headers ask for this so that the file stays a faithful trace.
3. Keep the label comment and the frame conventions of the file header.
4. Run the tests that read the file. For `surface.ts`, edit only the head or the affected `MazeEntry` rows; the file is long enough that editors struggle with it whole.

For `speech.ts` do not edit at all; change `speechLines.ts` and run `npm run speech`. For the local files, re-run the extractor.
