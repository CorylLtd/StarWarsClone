# Star Wars (Atari 1983) — POKEY sound effects: protocol, engine, and every effect as data

Companion data: `sound-effects.json` — for each effect (keyed by game-side name) the command byte, channel mask, per-channel raw phrase tables **and** the fully expanded register write list `{beat, ms, reg, value}` (AUDF/AUDC per POKEY channel), plus the protocol/engine/POKEY facts below. Cites `FILE:label`; numbers decimal unless `0x`.

## 1. Command protocol (main CPU → sound board)

* **Main side** (WSXMT.MAC:DOXMT, SNDPBX.MAC with `XMT=1`): every `AUDxx`/`PMxx`/`SPKxx` routine on the main board is a 2-instruction stub `LDA #ID; JMP DOXMT` generated by the `ID` macro; the IDs are the position in the PBX table. `DOXMT` polls `R.STAS` (0x4401) D7 for up to 14 × 15 cycles (≈210 cycles ≈ 140 µs) waiting for the previous byte to be consumed, then writes the byte to **`W.XMTS` (0x4400)**; on timeout it writes **0**, which is the sound board's *reset* command.
* **Sound side** (SNDAUX.MAC:RIRQ, DOCMD, INIT; SNDCMN.MAC memory map): the write latches the byte at `SIN` (0x0800) and raises PA7 of the 6532 → IRQ. The IRQ drains all pending bytes into a **32-entry circular FIFO** (`CMD`); byte 0 → immediate `INIT` (reset). The 4 ms mainline consumes **one command per tick** (`DOCMD`: index into the `PBX` word table, out-of-range values are dropped). The board answers the watchdog value `0x5A` (`PBX$OK`) on `SOUT` every tick; the main IRQ checks it once a second and resets the board (`W.RSTS`) if wrong (WSINT.MAC:IRQ).
* **Command bytes** (SNDPBX.MAC order, confirmed by the `IDA*`/`IDP*`/`IDS*` symbols in WSROOT.MAP): 0 reset; **1 `AUDTST`**; 2 `PMTST`; 3–26 speech (`SPKALW` 3, `ELE` 4, `FOA` 5, `FOR` 6, `GRE` 7, `HAV` 8, `HIT` 9, `I` 10, `IMO` 11, `LET` 12, `LOS` 13, `R2N` 14, `R2T` 15, `RED` 16, `REM` 17, `SHK` 18, `SIZ` 19, `SKP` 20, `STA` 21, `STR` 22, `THI` 23, `TRU` 24, `USE` 25, `YAU` 26); 27–37 music (`PMBEN` 27, `CNT` 28, `DAR` 29, `DES` 30, `END` 31, `4TH` 32, `REB` 33, `RRP` 34, `SF2` 35, `TH5` 36, `THB` 37); **effects: `AUDCR` 38, `AUDDF` 39, `AUDDR` 40, `AUDNAY` 41, `AUDPB` 42, `AUDPBZ` 43, `AUDPF` 44, `AUDPH` 45, `AUDPS` 46, `AUDRC` 47, `AUDRD` 48, `AUDRS` 49, `AUDRY` 50, `AUDSH` 51, `AUDSS` 52, `AUDSX` 53, `AUDTC` 54, `AUDTCZ` 55, `AUDTH` 56, `AUDTL` 57, `AUDXL` 58, `AUDYEA` 59.**
* **Dispatch on the sound board** (SNDAUD.MAC:AUDxx, AUDNEW): each effect routine loads the address of its *pointer block* (`XX0`, built by the `OFFSET` macro: 1 mask byte + up to 8 pairs of pointers) and calls `AUDNEW`, which for every channel in the mask copies the frequency-table and control-table pointers into that channel's two sequencer slots and sets their timer/repeat to 1. **There is no priority and no queue**: a new effect overwrites only the channels it uses; other channels keep playing. No effect loops. The "stop" commands (`AUDTCZ`, `AUDPBZ`) are effects whose tables are empty, so on the next beat the engine writes 0 to AUDF and AUDC of channels 6/7 (or 3/4), silencing them. Note the name swap: **`AUDXL` (main "X-wing laser") plays table `BL` (channels 1-2) and `AUDTC` (TIE cannon) plays table `XL` (channels 6-7)** — "switched for better effect".

## 2. The effect engine (SNDAUD.MAC:AUDDO; SNDAUX.MAC:MAIN, INIT)

* **Tick**: 6532 timer `E1024T` loaded with 6 → 6144 E-cycles ≈ **4.06 ms** at 1.512 MHz (12.096 MHz/8). `AUDDO` runs on even ticks → **one beat ≈ 8.13 ms** (the "every 16 mils" comment is stale). Music (`PKDR`) and speech run every tick.
* **Slots**: 16 sequencer slots (`AU.BLK`, 5 bytes each: pointer, timer, repeat, current value). Slot *k* writes POKEY register byte `0x1800 + k`, so slot 2n = AUDF and 2n+1 = AUDC of **effect channel n+1**: channels 1-4 → POKEY at **0x1800** ch1-4, channels 5-8 → POKEY at **0x1808** ch1-4. All effect channels are 8-bit.
* **Phrase format** (`.S RPT,TMR,SND,INC`, 4 bytes; list terminated by a 0 byte `.SZ`): on entry write `SND`; every `TMR` beats add `INC` (8-bit wrap) and write again; after `RPT` values move to the next phrase. Reaching the terminator writes **0** to the register and frees the slot. A phrase lasts `RPT × TMR` beats; the first write happens on the first beat after `AUDNEW` (0–8 ms latency). Frequency (`…nF`) and control (`…nC`) lists advance independently. Several F lists have no terminator of their own and run on into the following C data (harmless: by then the C list has written volume 0) — the JSON flags this (`freqListRunsPastCtrlList`) and gives `audibleBeats` = the C list length.
* **AUDCTL**: the two effect POKEYs get AUDCTL = **0** at reset and the engine never writes it (8-bit channels, "64 kHz" base, 17-bit poly, no high-pass, no joins). SKCTL is set to 3 then 7 at init.
* **FM / "vibrato-ambience"** (SNDAUX.MAC:MAIN): 6532 PA3 (active low) switches the board's analogue modulation on. It is on unless: speech is playing or pausing, any music voice is in use (`VIU ≠ 0`), diagnostics, or **the control pointer of effect channel 5 is at/after `VIBOFF`** — i.e. the R2 sounds (`RY, RD, RC, DR, RS`) and the test tones, which all live on channel 5 and after `VIBOFF`, are played dry; every other effect is played through the modulation (when no music/speech is active).

## 4. Channel sharing with music and speech

| Consumer | POKEY(s) | Configuration | Cite |
|---|---|---|---|
| Sound effects | 0x1800 (effect ch 1-4), 0x1808 (effect ch 5-8) | AUDCTL 0, eight 8-bit channels, unfiltered | SNDAUD.MAC:AUDDO, SNDAUX.MAC:INIT |
| Music (`PKDR`) | 0x1810 (`POKEY`) and 0x1818 (`POKEY2`) | AUDCTL **0x78** on both: ch1+2 joined (16-bit) at the full clock, ch3+4 joined at the full clock → **four 16-bit music voices**; these two chips are behind a **3.5 kHz low-pass filter** | SNDPM.MAC:ISND, POKEY equates |
| Speech | TMS5220 via 6532 port B | separate path; `SP.STA/SP.DLY` also gate the FM effect | SNDSPK.MAC, SNDAUX.MAC:MAIN |

So effects never contend with music for channels; the only interaction is the FM/ambience switch (§2) and the shared 4 ms scheduler.

## 5. POKEY facts for a software model

* **Clock**: MAME's `starwars` driver clocks all four POKEYs at **1.5 MHz** (the 6809 E clock is 12.096 MHz / 8 = 1.512 MHz). *(From memory of MAME; not in this source set — verify.)*
* **Base rates** (AUDCTL bit 0 = 0): "64 kHz" = clock/28 = **53.6 kHz** at 1.5 MHz (63.9 kHz on a 1.79 MHz chip); bit 0 = 1 → "15 kHz" = clock/114 = 13.2 kHz. Channels 1/3 can be switched to the full clock (AUDCTL 0x40 / 0x20); 0x10 / 0x08 join channels 2+1 / 4+3 into 16-bit dividers; 0x04 / 0x02 high-pass ch1 by ch3 / ch2 by ch4; 0x80 selects the 9-bit instead of the 17-bit poly.
* **Frequency**: 8-bit channel at the base rate: `f = base / (2·(AUDF+1))`; channel at the full clock: `f = clock / (2·(AUDF+4))`; 16-bit pair at the full clock: `f = clock / (2·(AUDF16+7))`. The effects use only the first form with base 53.6 kHz (e.g. laser AUDF 55 → 479 Hz sweeping down to AUDF 251 → 106 Hz; shield hit AUDF 3 → 6.7 kHz; Death Star AUDF 70-78 → 377-339 Hz noise).
* **AUDC**: bits 7-5 distortion — 0: 5-bit poly ∧ 17-bit poly; 1: 5-bit poly; 2: 5-bit ∧ 4-bit poly; 3: 5-bit; 4: 17-bit poly; 5: pure tone; 6: 4-bit poly; 7: pure tone. Bit 4: volume-only (DC) output. Bits 3-0: volume 0-15. The polynomial counters (4-, 5-, 17/9-bit) are free-running LFSRs sampled by the channel divider; MAME's `pokey.cpp` implements them exactly. Effects here use: pure tone (`0xA_`), 17-bit noise (`0x8_`), 4-bit poly (`0xC_`), 5-bit∧4-bit (`0x4_`), 5-bit (`0x2_`), 5-bit∧17-bit (`0x0_`).
* **Mixing**: four channels per chip are summed on-chip; the board then applies the FM/ambience stage to the effect chips and the 3.5 kHz filter to the music chips before the stereo output (SNDCMN.MAC hardware comment "vibrato/ambience super stereo").

## 6. Open questions

1. POKEY clock (1.5 MHz) is quoted from memory of MAME's driver, and the `POKEY.DAT` documentation referenced by SNDAUD.MAC is not in this source set; the divider formulas are the standard POKEY ones.
2. The exact analogue behaviour of the "FM" (PA3) modulation and the stereo/ambience circuit is hardware, not software; a software model can treat it as an optional tremolo/chorus on the effect chips.
3. The 4 ms tick assumes the 6532's timer runs from the 1.512 MHz E clock; if the 6532 is clocked differently the beat scales accordingly (the ratio "every 8 ms" is what matters for expansion).
4. Several F lists overrun into following data (crash, shield, pass-by, Death Star, laser …); the JSON expands them faithfully but marks the audible portion — a re-implementation only needs the audible part.
5. AUDTST/AUDYEA/AUDNAY are diagnostics; PM/SPK commands are listed for completeness but music and speech content are outside this document.
